# Security Policy

## Reporting a vulnerability

**Please do not open a public issue for a security problem.**

Use GitHub's private vulnerability reporting for this repository:
**Security → Report a vulnerability**. That channel is private to the maintainer
and gives you a thread to work in.

Please include what you need to make the problem reproducible: the version or
commit, the steps, and what you observed. A proof of concept helps; keep it in
the private thread.

## What happens next

- **Acknowledgement:** within 7 days.
- **Assessment:** you get an initial judgement — accepted, not a vulnerability,
  or needs more information — with the reasoning.
- **Fix and disclosure:** coordinated with you. You are credited unless you ask
  not to be.

This is a personal project, not a company with a duty roster. The timelines
above are honest intentions, not a contractual SLA.

## Scope

The code in this repository. Not in scope: the author's own infrastructure,
websites or accounts, and third-party dependencies (report those upstream —
though a note here is welcome).

## Secrets

If you find a credential, key or token committed anywhere in this repository or
its history, that is a valid report and an urgent one. Please use the private
channel above rather than demonstrating it publicly.
